# 知乎 AI 共读养成游戏：首个可玩版本 v1

这是首个十二档案纵向切片。玩家与“小助手”一起阅读材料；前两条保留医院与转行的基础体验，后续熟人会带着上一次共读留下的新问题继续回来。

```text
检查材料 → 有限取舍 → 两份素材左右进入整理桌 → 提交给伙伴 → 伙伴把素材拆成四张卡牌直接摆上整理桌
→ 点卡查看正文 → 卡牌出现在知乎评论区 → 发出评论并进入回合制回访 → 进度 3 时提问者感谢并结束
→ 回信后出现三张动作卡：追问 / 安抚 / 出去看看 → 继续完成回访对话
→ 奖励到账并收录进图鉴 → 房间留下痕迹 → 旧判断在下一章重新出现
```

## v1 内容

- 首次进入 v2 会显示六页新手教程：共读目标、两个窗口的分工、阅读选材、回复卡、按耐心与三格进度推进的回访，以及奖励与图鉴；任务栏的“教程”可以随时从第一页重看，也可以跳过，不会改变 12 条流程。
- 档案 00：大学生第一次独自去医院。玩家处理当前规则、旧高赞回答、个人经历和题主条件。
- 档案 01：只有三个月存款，是否裸辞转行。这里没有唯一官方答案，材料分别承担市场参照、方法、风险和本人处境。
- 档案 02—11：十条连续的熟人回访，林一舟、小满、老 K、周阿姨和过客角色会带着真实的新处境回来，包括医保分流、作品反馈、租房沟通、面试跟进、复诊记录、试用期边界、课程选择、offer 核对与下一步决定。
- 每条档案都有一篇完整求助帖、四份可展开的长素材、两份素材各自拆出的卡牌、发给提问者的完整话术和按状态推进的评论区回应；短卡面只保留判断摘要，展开后才读到完整正文。
- 第一章的“允许伙伴先质疑”或“要求共同核对”会改变第二章第一次调查动作。
- 第二章有三种行为结果，但不向玩家显示人格数值或路线标签；差异通过回信、房间物件、札记和伙伴动作表达。
- 材料递交有 320ms 跨窗演出；伙伴具有接收、检查、迟疑、确认和等待五种独立情绪状态。
- 低等级的选材阶段不要求玩家手动分类；两份素材先在整理桌左右并排，必须提交给伙伴后才会拆成四张卡牌并直接呈现。卡牌采用原创收藏卡面：中间是正文，底部显示“对策卡 / 共情卡 / 追问卡”等类型，来源卡单独保留作者、日期与使用边界。点击整理桌上的卡牌即可查看详情并带回知乎评论区，评论发出后仍可回桌面选择下一张，后续再做最终回复判断。
- 评论区回访不预设固定回合数：每回合根据三格进度与楼主耐心推进；三格全部点亮时由提问者用完整的话感谢共读答主并结算奖励，耐心归零则提前结束。前 11 条结束后可以继续下一条熟人求助，第 12 条结束后才显示“十二条求助完成”。奖励、伙伴档案、已提取的回复卡和发给提问者的完整评论会累计进入知乎“图鉴”入口。
- 第一章的票据、材料书和记忆灯分阶段加入固定房间；第二章结束后，伙伴会主动放下一张不是玩家递交的折页。

桌面窗口支持拖动、最小化、最大化、关闭、桌面图标重开和任务栏恢复。房间支持小窗对照与最大化聚焦，所有新增物件在普通与聚焦尺度下均保持可读。

## 运行

需要 Node.js。进入本目录后运行：

```powershell
npm start
```

然后打开 `http://127.0.0.1:4173/`。根地址与 `/v1.html` 均进入 v1；旧版仍保留在 `/art-v0.2.html`。

## 当前内容边界

- 所有问题、回答、评论、医院名称和流程均为游戏虚构示例。
- 不读取玩家的知乎账号、收藏、浏览历史或电脑文件。
- 当前不调用知乎搜索 API 或知答 API；两章材料均为本地虚构数据。
- “共读札记”默认关闭，只以自然语言记录具体经历；人格数值和触发条件不会展示给玩家。
- 医院章节不提供疾病诊断或现实医疗流程承诺；转行章节不构成职业或财务建议。
- v1 是完整可玩的十二档案原型，不代表最终内容量、存档系统或联网版本。
