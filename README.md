# 共读模式 Co-Read OS · 知乎黑客松2026 参赛项目

一个像素风的叙事共读游戏：你和房间里的 AI 共读伙伴「00」一起，读知乎提问者的材料，
核对作者与日期，共同决定怎么写一封公开回答。回答发出去之后，提问者和评论区会记住你们怎么选。

## 核心立意

AI 时代的知识社区，缺的不是"能生成答案的模型"，而是**帮人看清一条信息可不可信的共读习惯**。
玩家在游戏里练习的正是这件事：先看署名和日期，再决定信什么；AI 辅助整理，人做最终决定。

## 三大系统

### 1. 检查点存档（save-system.js）
- 在每个场景入口（选材料 / 整理 / 草稿 / 发送 / 回访 / 章节切换 / 结局）自动写入 localStorage；
- 启动页出现「继续上次共读」，可从最近检查点完整恢复（含隐藏属性、札记、房间陈设）；
- 对话进行中的小段进度刷新后回到场景开头，保证属性数值不会重复累计。

### 2. 旧版 AI 增强（仅历史代码）
游戏内「AI 增强 · 系统设置」（顶栏指示灯点击进入）可接入任意 OpenAI 兼容端点
（内置智谱 GLM / DeepSeek 预设），Key 只存本机。提供三个能力点，全部带脚本兜底：
- 伙伴动态反应：递材料、贴标签、开始整理时，LLM 以 00 的口吻实时生成独白，驱动 5 种情绪立绘；
- 共写回答助手：草稿工坊中 00 会试写一句回答开头，玩家仍然拍板——AI 辅助、人做主；
- AI 共读 · 换你出题（结局页入口）：粘贴任意知乎风格问题，LLM 结构化为一份完整可玩档案
  （4 份带作者/日期的材料、来源标签、3 个决定、3 个草稿思路、次日回访），走完整章节流程。

关闭 AI 或断网时全部功能静默回退到内置脚本，演示永不翻车。

> 以上是旧版 v1 的历史能力。当前 v2 已按离线演示要求移除系统设置和真实 API 入口，只使用内置剧本与本地建议。

### 3. 双章叙事 + 隐藏属性（app-v1.js）
- 档案 00「第一次独自去医院」/ 档案 01「该不该裸辞转行」，材料误标会产生真实后果与回访纠纷；
- 4 个隐藏属性（求真 / 共情 / 行动 / 审慎）贯穿两章并改变结局；伙伴会记住你的每次选择。

## 测试

- smoke.mjs：静态结构 / 台词 / 接线冒烟测试；
- test-save.mjs：jsdom 真实运行游戏脚本，验证存档写入、刷新恢复、检查点一致性（20 项断言）。

## v2 · 回答主游戏（当前开发版，机制按设计总览 v1.1）

- 入口：/v2.html（旧版共读叙事原型保留在 / 供参考，不再迭代）
- 一局流程：接求助 → 共读（注意力选 2 份材料，从伙伴划出的候选句里挑 ≤3 句做成素材卡并标来源）→ 打「回答方式」牌与求助者对话（共情/追问/建议/案例/清单/利弊，消耗他的耐心）→ 状态轴实时反馈 → 结算 → 几天后收到回信（过时信息此刻暴露）
- 桌面即电脑：Bliss 壁纸 + Windows 软件图标 + 可拖动窗口 + 右侧卧室常驻面板（伙伴固定在房间里，由玩家手动查看和推进）
- 系统清单：注意力/耐心/状态三资源、素材卡三档（精华/普通/废卡）、组合加成、熟练度与粉丝成长、检查点存档（刷新可续玩）、每阶段一次性新手指引；v2 离线运行，不接真实 API
- 文案：挂号题 demo 包见 docs/挂号题文案包.md（由 game/question-pack.js 自动导出，队友改 question-pack.js 再导出即可）
